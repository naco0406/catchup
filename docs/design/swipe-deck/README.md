# 밀기 시안 — 캐치업 덱

2026-11-22 · 화면 시안 v1 · 구현 전

오른쪽으로 밀면 추천대로, 왼쪽으로 밀면 미루기(Q7)를 어떻게 보여 줄지 다시 그린 시안이에요. 지금 구현(떠 있는 알약)을 진단하고, 레퍼런스를 조사해 방향 셋을 견준 뒤 A(추천 답이 차오르고, 토스트가 미리 보여요)를 그렸어요.

## 파일

| 파일 | 내용 |
|---|---|
| `swipe-deck.html` | 시안 보드(한 파일로 묶은 것). 브라우저로 열어요. 4장에서 직접 밀어 볼 수 있어요 |
| `board.html` | 보드 원본(그림 파일을 따로 읽어요) |
| `src/board.tpl.html` | 보드의 글 |
| `src/screens.py` | 화면 조각을 만드는 곳. 같은 카드를 상태(`--dx` · `--p`)만 바꿔 그려요. 밀어 보는 칸의 스크립트도 여기 있어요 |
| `src/swipe-kit.css` | 이 시안이 더하는 상태(차오르는 답 · 미리 보이는 토스트 · 덱). 값은 모두 `tokens.css` 변수예요 |
| `src/learn-*.html` · `src/refs*.html` | 레퍼런스에서 배운 것과 출처 |
| `harness/` | 지금 화면을 진짜 터치로 밀어서 찍는 Playwright 스크립트 |
| `shots/` | 지금 화면 캡처, 잰 값(`probe.json`), 진단 핀 자리(`pins.json`) |
| `check/` | 장마다 찍은 그림과 검사 결과 |

## 다시 굽기

```bash
zsh docs/design/swipe-deck/build.sh
```

- 순서: 조립 → 아이콘 → 핀 → 밀어 보는 칸의 스크립트 넣기 → 검사 → 한 파일로 묶기.
- 스크립트를 핀 다음에 넣는 이유: 핀을 놓는 도구가 문서의 마지막 스크립트를 지우고, 그때 화면에 그려진 모습을 그대로 저장해요.
- 도구 경로는 `../decision-inbox/env.sh`를 같이 써요.

## 지금 화면 다시 찍기

```bash
cd apps/web && npx playwright test --config ../../docs/design/swipe-deck/harness/capture.config.mjs
```

예시 자료 모드(포트 5180)로 띄워 찍어요. 서버나 실제 계정은 쓰지 않아요.
