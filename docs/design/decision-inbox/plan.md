## 순서를 이렇게 잡은 이유

- **화면을 먼저 손에 쥐어요.** 이 제품의 값은 '빠르게 정해진다'는 느낌이에요. 서버를 만들기 전에 예시 카드로 써 보고 카드 틀을 고쳐요.
- **처음부터 클라우드예요.** 기기가 꺼져 있어도 비서가 일해야 해서, 2단계부터 사용자 칸(개인 서버) 위에 만들어요.
- **진짜 카드는 코딩 에이전트에서 먼저 받아요.** Claude Code와 Codex의 질문은 선택지가 붙어 와서, 비서가 카드를 지어낼 필요가 없어요.
- **메일은 평가 세트부터.** 가르기가 틀리면 제품을 믿을 수 없어요. 문항을 먼저 만들고 '놓친 결정 0'을 확인한 뒤 붙여요.
- **신청은 모두 보류해요(Q11).** 코딩 에이전트부터 하는 동안은 필요 없어요. Gmail 보안 심사 · 카카오 채널 인증 · Slack 마켓플레이스는 4~6단계 전에 다시 꺼내요.
- **알아서 하기는 답이 쌓인 뒤에.** 맡길 근거가 처리 기록에서 나와요.

## 1단계 — 화면 프로토타입

> **진행(2026-11-21): 만들었어요 — `apps/web`.** Rust 서버 없이 TypeScript · React · Vite로, 예시 카드 20장(한국어 · 영어)으로 돌아요.
> 자동으로 확인한 것: 아이패드 가로에서 누르기만으로 7장 · 키보드(1~4 · ↵ · S · D)만으로 7장 · 아이폰 390에서 누르기 · 밀기로 7장 · 영어로 바꿔도 20장 모두 넘침 없음 · 10초 되돌리기 · 위험한 답은 두 번 · 새로 고침해도 답이 사라지지 않음(e2e 26개, 단위 22개).
> 남은 것: **소유자가 실제 아이패드 · 아이폰에서 써 보고 고칠 점을 적는 것**(아래 마지막 기준). 이건 사람이 해야 해요.

- 범위: 보드의 화면을 웹으로 만들어요. 카드 덱, 선택지와 번호 키, 주관식 입력과 다시 만든 선택지, 미루기, 되돌리기, 다 봤어요, 처리 기록, 처음 화면(연결 목록), 좁은 화면.
- 디자인: `docs/design-system/tokens.css` · `components.css`를 앱의 토큰 · 컴포넌트로 옮겨요. 화면에 즉석 값을 넣지 않아요.
- 언어: 화면 문구는 한국어 · 영어 두 가지예요. 처음부터 번역 파일에 모으고, 화면 코드에 글을 박지 않아요.
- 바탕: CatchUp 레포에 pnpm 작업 공간과 TypeScript · React · Vite 웹 앱을 만들어요. 판은 AI1과 같은 데서 시작해 고정해요. 서버(Rust)는 2단계에서 만들어요.
- 데이터: 예시 카드 20장쯤을 파일로 둬요. 보드의 일곱 장에 실제 상황을 닮은 것(카카오톡 · 슬랙의 짧은 말 포함)을 더해요.
- 끝났다고 보는 기준:
  - 아이패드 Safari에서 카드 7장을 키보드 없이 끝까지 넘길 수 있어요.
  - 블루투스 키보드로 1~4 · ↵ · S · D만 써서 끝까지 넘길 수 있어요.
  - 아이폰 Safari(390 폭)에서 같은 7장을 엄지로 끝까지 넘길 수 있어요.
  - 언어를 영어로 바꿔도 화면이 깨지지 않아요(긴 영어 문구로 넘침 검사).
  - 직접 써 본 뒤 카드 틀에서 고칠 것을 적어 보드에 반영했어요.
- 위험: 예시 카드가 실제보다 깔끔해서 쓰임새를 잘못 판단해요. 그래서 3단계에서 바로 진짜 카드를 받아요.

## 2단계 — 클라우드 뼈대와 카드 API

- 범위:
  - 공용 앞단(계정 · 로그인 · 기기 · 웹훅 받기)과 사용자 칸(데이터 · 일꾼). 모든 표 · 큐 · 로그의 첫 열쇠는 칸 ID예요.
  - `decision_cards` · `card_turns` · `card_answers` · `action_receipts` 표, 카드 목록 · 흐름(SSE) · 답 · 미루기 · 내가 직접 · 되돌리기 길. 거절과 그 이유를 남기는 길.
  - 연결 토큰 · 모델 키를 칸 키로 암호화해 두기, 웹 푸시.
- 끝났다고 보는 기준:
  - 손으로 넣은 카드에 1단계 화면에서 답하면 영수증이 남고 되돌릴 수 있어요.
  - 같은 답을 두 번 보내도 한 번만 실행돼요.
  - 실행 전에 원본이 바뀐 경우 실행하지 않고 카드가 고쳐져요.
  - 실패한 실행이 `failed` 카드로 다시 올라와요.
  - 서버를 다시 켜도 열린 카드와 진행 중인 실행이 이어지고, 두 번 실행되지 않아요.
  - 한 칸의 일꾼을 일부러 죽여도 다른 칸의 카드는 계속 와요. 한 칸이 다른 칸의 줄을 읽지 못하는 경계 시험이 CI에 있어요.
  - 누가 기다리는 카드와 기한이 오늘인 카드만 알림으로 와요.
- 측정: 답 요청의 지연, SSE로 새 카드가 닿는 시간, 다시 켰을 때 이어지는 데 걸린 시간을 `docs/performance/`에 남겨요.

## 3단계 — 코딩 에이전트 카드(클라우드 샌드박스, Codex부터)

- 범위:
  - **Codex 로그인(임시, Q10)**: AI1처럼 칸마다 `codex app-server`(판 고정) 하나를 띄우고, 전용 `CODEX_HOME`에 ChatGPT 로그인을 둬요. 클라우드라 기기 코드 로그인으로 웹 화면에서 로그인해요. `auth.json`은 칸 키로 암호화해 두고, 갱신되면 되써요. 로그인 풀림 · 한도 찼음은 카드로 올려요.
  - **LLM 창구**: AI1처럼 OpenAI Responses 모양(`/v1/models` · `/v1/responses`)의 내부 창구로 LLM을 불러요. 도구는 끄고, 쓰기 시작하면 그 차례를 멈춰요. 이후 단계의 가르기 · 카드 만들기가 이 창구를 써요.
  - **Codex 코딩 세션**: 내 칸의 샌드박스에서 같은 로그인으로 Codex 세션을 돌려요(쓰기 허용 · 승인은 카드로). 승인 요청과 `tool/requestUserInput`을 카드로 만들고 답을 돌려줘요. 저장소는 GitHub 연결로 받아요.
  - 사이드바의 '비서가 하는 일'에 세션 상태를 보여 줘요.
  - 인증은 갈아 끼울 수 있게 둬요. 다른 사람에게 열기 전에 API 키 · SIWC로 바꿔요(Codex app-server의 ChatGPT 로그인은 호스팅 서비스에 허용되지 않아요).
  - Claude Code는 Q14가 정해진 뒤에 같은 틀(Agent SDK의 `canUseTool` · `defer` 훅)로 붙여요.
  - 보조 길(선택): 사용자 PC에서 돌던 세션에 붙기 — Codex는 작은 훅 스크립트. **사용자 PC에 설정을 넣는 길**이라 '모두 클라우드'의 예외로 적어 둬요.
- 먼저 확인할 것: app-server로 기기 코드 로그인을 시작할 수 있는지(안 되면 `codex login --device-auth`를 칸에서 돌려요). 0.163.0 이후 판에서 바뀐 것.
- 끝났다고 보는 기준:
  - 웹에서 Codex 로그인을 끝내면 칸에 로그인이 남고, 일꾼을 다시 켜도 다시 로그인하지 않아도 돼요.
  - LLM 창구로 짧은 질문에 답을 받아요. 도구를 쓰려 하면 멈춰요.
  - 클라우드에서 돌던 Codex의 명령 실행 승인을 웹에서 하면 그 명령이 실행돼요. 질문에 답하면 세션이 이어져요.
  - 답을 한 시간 뒤에 해도 세션이 이어져요.
  - 샌드박스가 죽었다 다시 떠도 열린 카드가 사라지지 않고, 같은 카드가 두 번 생기지 않아요.
  - 한도가 차거나 로그인이 풀리면 그 칸에 카드가 올라오고, 다른 칸은 그대로예요.
  - 샌드박스에 운영 자격 증명이 없어요(검사로 확인).
- 측정: LLM 창구의 첫 글자까지 시간, 에이전트가 답을 기다린 시간, 샌드박스 띄우는 시간, 세션당 메모리를 `docs/performance/`에 남겨요.
- 위험: 실험 기능(Codex의 질문, 기기 코드 로그인)이 바뀔 수 있어요. 판을 고정하고 올릴 때 다시 확인해요.

## 4단계 — Gmail · Google 캘린더와 가르기

- 범위:
  - Gmail · Google 캘린더 연결(읽기, 답장 초안과 보내기, 일정 수락 · 거절 · 옮기기, 빈 시간 찾기). 새 메일은 Pub/Sub 푸시로 받아요.
  - 가르기와 카드 만들기. 알려만 묶음. 처음에는 '알아서'가 꺼져 있어요.
- 먼저 할 것: 평가 세트. 실제 메일과 일정에서 문항을 골라 '카드여야 하는가'와 '좋은 선택지는 무엇인가'를 손으로 달아요. 조종하려는 글도 넣어요.
- 공개 전: Gmail 제한 범위 검증(CASA). 그전에는 시험 사용자 안에서만 써요.
- 끝났다고 보는 기준:
  - 평가 세트에서 놓친 결정이 0이에요. 잘못 올라온 카드의 비율을 재서 기록해요.
  - 조종 문항에서 따라 한 것이 0이에요.
  - 일주일 동안 실제로 쓰면서 매일 '카드로' 고친 수와 '카드가 아니었다'고 넘긴 수를 기록했어요.
  - 답장이 10초 뒤에 나가고, 그 안에 되돌리면 나가지 않아요.
  - 한 연결의 토큰이 만료돼도 다른 연결의 카드는 계속 와요.
- 측정: 가르기 정확도, 카드 한 장을 만드는 시간과 값, 카드 한 장을 정하는 데 걸린 시간을 `docs/performance/`에 남겨요.

## 5단계 — Slack

- 범위: 나를 부른 글과 개인 메시지를 실시간 이벤트로 받아 가르고, 스레드에 답장해요. 데이터는 오래 보관하지 않아요.
- 끝났다고 보는 기준: 평가 세트에 Slack 문항을 더해 놓친 결정 0, 답장이 스레드에 10초 뒤 나가요, 마켓플레이스 심사에 낼 준비가 됐어요.
- 위험: 마켓플레이스 전에는 기록 조회가 분당 1회라, 이벤트를 놓치면 다시 읽기 어려워요. 이벤트를 받은 즉시 저장해요.

## 6단계 — 카카오톡

차례로 하나씩 올려요.

1. **채널 챗봇 + 나에게 보내기**(☁️): 결정 카드가 카톡으로 도착하고, 채널 대화방의 단추로 골라요. 카톡에서 본 글을 채널에 붙여 넣으면 카드가 돼요.
   - 끝났다고 보는 기준: 카톡에서 카드 하나를 끝까지 정할 수 있어요. 챗봇이 5초 안에 답하거나 콜백으로 답해요. 웹에서 정한 카드는 카톡에서도 닫혀요.
2. **대화 내보내기 올리기**(☁️ + ✋): 단톡방 따라잡기. 답장은 초안 복사예요.
3. **안드로이드 동반 앱**(📱, 선택형 베타): **보류**(Q13). 꺼내면 법률 검토부터 받아요.
4. **카카오 협력 문의**: 카나나 스페이스 외부 에이전트, PlayMCP.

- 하지 않는 것: PC 카톡 원격 조작, 비공식 프로토콜 클라이언트.

## 7단계 — 커넥터 넓히기

조사의 순서대로 하나씩 올려요. 커넥터마다 평가 문항 몇 개와 '토큰 만료 시 그 연결만 멈춘다' 시험을 같이 넣어요.

1. 공식 API가 좋은 것(☁️): Outlook · Microsoft 365, Telegram 비즈니스 봇, GitHub, Linear, Jira, Notion, 채널톡, 네이버웍스.
2. 사람 손이 한 번 필요한 것(☁️ + ✋): 네이버 메일, 다음 메일, iCloud 캘린더(앱 비밀번호).
3. 제한이 큰 것: Instagram · Facebook 메시지(프로페셔널 계정 · 페이지만), X DM(건당 과금), Teams(관리자 승인).
4. 보류: LinkedIn 메시지(파트너만), WhatsApp(범용 AI 비서 금지), iMessage(Mac 필요).

## 8단계 — 알아서 하기와 그다음

차례로, 하나씩 따로 올려요.

1. 알아서 하기: 같은 답 5번이면 제안, 끌 수 없는 규칙, 되돌리면 깎기.
2. 잠금 화면에서 답하기(위험 없는 카드만).
3. SwiftUI 앱(아이패드 · 아이폰). 디자인 시스템 토큰을 Swift로 옮겨요.
4. 가르기 모델 학습: 쌓인 답으로 작은 모델을 학습해 큰 모델과 비교해요.

## 재는 것

| 무엇 | 왜 |
|---|---|
| 카드 한 장을 정하는 데 걸린 시간 | 이 제품이 약속하는 것이에요 |
| 추천대로 고른 비율 | 추천의 질 |
| 주관식으로 답한 비율 | 선택지의 질. 높으면 선택지가 빗나가는 거예요 |
| '카드로' 고친 수 | 놓칠 뻔한 결정 |
| '내가 직접' · 넘긴 수 | 카드가 아니었던 것 |
| 하루 카드 수 | 또 하나의 받은함이 되고 있는지 |
| 에이전트가 답을 기다린 시간 | 코딩 에이전트 쪽 효과 |
| 되돌린 수 | 잘못 정했거나 잘못 실행한 것 |
| 사용자 칸 하나의 한 달 비용 | '개인 서버 한 대' 구조가 감당되는지 |
| 커넥터별 실패 · 재연결 수 | 어느 연결이 약한지 |

## 하지 않기로 한 것(1차)

- 여러 사람이 함께 쓰는 팀 기능.
- 메일 · 메신저 원문을 읽는 화면. 원문은 원래 앱에서 열어요.
- 다크 모드 화면. 토큰 짝만 정해 뒀어요(`docs/design-system/tokens.css`).
- 카드 순서를 내가 정하는 기능. 비서가 기한과 기다림으로 세워요.
- 약관이 막는 연결(PC 카톡 원격 조작, 비공식 프로토콜 클라이언트, 구독 토큰을 모아 대신 돌리기).
